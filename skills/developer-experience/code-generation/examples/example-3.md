# Example 3 — Nondeterministic output from an unpinned generator

## Before

The generator is installed globally on each machine ("install the latest").
Two developers regenerate the same unchanged spec a week apart:

```diff
-// Generated 2026-11-14 by openapi-generator 7.9.0
+// Generated 2026-11-21 by openapi-generator 7.10.0
 export interface Invoice {
-  id: string;
-  total: number;
+  total: number;
+  id: string;
 }
```

The diff touches hundreds of files: a version bump in every header, fields
reordered, timestamps changed. The one real spec change buried in the same
regeneration is unreviewable, and neither developer can say which output is
correct.

## After

The generator is pinned like any other dependency, headers carry no
timestamps, and regeneration is a recorded project command:

```json
// package.json (excerpt)
{
  "devDependencies": { "@openapitools/openapi-generator-cli": "7.10.0" },
  "scripts": { "generate:api": "openapi-generator-cli generate -g typescript-fetch -i api/openapi.yaml -o src/api/generated" }
}
```

```ts
// src/api/generated/models/Invoice.ts
// @generated by openapi-generator 7.10.0 from api/openapi.yaml — do not edit.
export interface Invoice {
  id: string;
  total: number;
}
```

Regenerating the unchanged spec now produces zero diff on any machine
(G-DX-021), and running it twice produces identical file hashes
(G-DX-022). A generator upgrade becomes its own deliberate change: pin
bumped, output regenerated, diff reviewed on its own.

Note: corrects DX-044 and DX-045 — the generator and its version are pinned in the manifest and lockfile, and the same source plus the same generator version produces byte-identical output on any machine.
