# Example 1 — A hand-edited client, fixed at the source

## Before

The API client is generated from `api/openapi.yaml`. A developer needs one
extra validation rule on the `CreateOrder` request, so they edit the
generated file directly:

```ts
// src/api/generated/client.ts — generated, then hand-edited
export function createOrder(req: CreateOrderRequest) {
  if (!req.customerId) throw new Error("customerId required"); // hand edit
  return http.post("/orders", req);
}
```

Nothing records the edit. Two weeks later the spec changes for an unrelated
reason, the client is regenerated, and the validation silently disappears.
The server starts receiving orders with no customer ID.

## After

The rule belongs to the API contract, so it is changed in the source of
truth and the client is regenerated:

```yaml
# api/openapi.yaml
CreateOrderRequest:
  type: object
  required: [customerId, items]
  properties:
    customerId: { type: string, minLength: 1 }
    items: { type: array, minItems: 1 }
```

```ts
// src/api/generated/client.ts
// @generated by openapi-generator 7.x from api/openapi.yaml — do not edit.
export function createOrder(req: CreateOrderRequest) {
  return http.post("/orders", req);
}
```

The regenerated types now reject a missing `customerId` at compile time,
the drift check (G-DX-021) proves output matches source, and the change is
reviewable as a spec diff — not discoverable as a production bug.

Note: corrects DX-042 — generated output is never hand-edited; the change is made in the source or template, then regenerated.
