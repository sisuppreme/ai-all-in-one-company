# Example 2 — The 24/7 default replaced with real hours

## Before

A one-person team installs the messenger with vendor defaults and launches
the same day. The tool's default availability is 24/7, so the widget shows
"Live chat — typically replies in a few minutes" around the clock. A user
messages at 11 p.m., watches the "online" indicator, gets no reply until
the next afternoon, and opens a chargeback dispute instead of a second
message.

## After

Before launch, the operator configures the tool from their real week:

1. Office hours set to the hours actually staffed (weekdays, 9 a.m.–6 p.m.
   in the operator's timezone); expected reply time set to the honest
   in-hours figure.
2. The widget copy reads "Message us," not "Live chat."
3. Outside hours the widget states when the team returns, shows the
   expected reply time, and captures the message as a ticket with a
   reference number.
4. G-CX-014 diffs the site copy against the configuration; G-CX-013 runs
   the offline path with the clock set outside hours.

The promise shrank. It is now a promise the system is configured to keep.

Note: corrects CX-023 and CX-024 — hours and reply expectations are configured from real availability before launch, and the offline state is honest and captures a ticket.
