# Example 2 — Finding a theme: index first, spec before building

Corrects rule **FE-341** (build from the canonical expanded spec) and BAN-FE-171 (building from the index, a summary, or memory).

## Before

A builder needs "the sonar one" for a survey company's site. Working from the catalogue card and memory of a demo, they improvise: dark green background, a rotating sweep conic-gradient, beeping hover sounds, and sections stacked as identical cards. The result borrows the theme's name and none of its system — no dive sheet, no depth geography, no ping discipline — and it fails the merge test on every element: delete the sweep and the page loses nothing but decoration.

## After

The builder opens the range index `themes-051-075.md`, finds theme #63 Sonar Room, and follows its pointer to the canonical spec, `expanded/theme-063.md` — reading it end to end before designing. The decision record (design-intelligence) cites that file. The build now follows the spec: the page is sounded, not scrolled — depth is its geography, the five contacts on the scope are the dive sheet's own contacts, the metres-to-fathoms flip past 1,000 m and the lengthening ping interval are built to §6's millisecond choreography, and pressure climbs by the printed rule P = 1 + d/10. Gate G-FE-171 spot-checks palette anchors, type pairing, and signature elements against the expanded file — all match, because the file was the source.
