# Example 2 — E-commerce storefront: template shop replaced by one theme adopted whole

Corrects rules **FE-363** (theme is decided, never drifted), **FE-364** (passes run whole-app, in order), **FE-365** (a full motion system ships on every page), and **FE-370** (the UI speaks only user-facing concepts).

## Before

A small e-commerce storefront is the framework starter with a palette swap: gradient hero, centred-everything composition, perfectly even product grids, identical fade-up on all fourteen sections, a spinning 3D logo covering the hero copy, and counters animating round invented numbers ("10,000+ happy customers", unsourced). The shop has no identity — change the logo and it could sell anything. Motion was added per page by feel: the catalogue pins, the product page scrubs, checkout bounces. The product page also leaks: a "Tech specs" tab lists the stack ("Built with Next.js + Stripe API v3, products table, 4 routes") instead of anything a buyer needs.

## After

The audit scores the shop 28/80 BEFORE, with the invented counters, the pasted-on logo, and the stack tab all listed as defects. The theme decision (FE-363) adopts one library theme whole — a material/craft family theme chosen by the design-intelligence decision process for a handmade-goods shop — from its canonical expanded spec: warm material palette, serif display + humanist body, vessel/fabric vocabulary, dial 3 on story and catalogue pages, dial 1 at checkout. The staged passes (FE-364) run whole-app in order: pass 1 tokenises the palette so the shop stops being seven greys; pass 4 gives every product card its full state set (including out-of-stock and loading states that used to be blank); pass 5 installs the full motion system (FE-365) in the theme's own language — staggered masked reveals on the catalogue, the product's own material reassembling in the hero as the visitor scrolls its story, a marquee of real maker names, counters only where real figures exist (orders actually shipped, makers actually stocked). The spinning logo is cut: it failed the merge test. The "Tech specs" tab is rebuilt around the buyer (FE-370) — materials, care, delivery, returns — with no DB names, no table names, no tech-stack labels, no endpoint or route counts anywhere on the site. AFTER score 69/80, AFTER leak score 0, and checkout — deliberately the quietest page in the app — converts exactly as before, verified against the frozen baseline.
