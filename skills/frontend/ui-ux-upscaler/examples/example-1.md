# Example 1 — Internal analytics dashboard: starter grey replaced by a deepened identity

Corrects rules **FE-361** (audit first, no silent restyle), **FE-363** (theme is decided, never drifted), **FE-366** (signature elements are merged, 5–20 per app), and **FE-369** (use the internals to understand, never to show).

## Before

A three-year-old internal analytics dashboard ships in framework-starter grey: default font pairing, uniform card grids, identical fade-up reveals on every section, a heavy custom cursor trailing the pointer, and no token source — seven greys and five unrelated timings across twelve pages. The audit (written after the fact, to justify a restyle already half-done) scores it 31/80: dead sections everywhere, the footer an afterthought grid, charts that read as screenshots. Worse, the UI leaks the machinery: the sidebar nav lists "users_table" and "events_collection", an empty state reads "No rows in events_collection", and an error banner shows `ERR_POSTGRES_23505`. Engineers call it "the navy board" — but there is no navy anywhere in the UI; the identity exists only in conversation.

## After

The upgrade starts with the audit (FE-361): `UI-UPGRADE-AUDIT.md` lists every page, every slop symptom with its anti-slop row number, every missing system, the heavy cursor, and nine leaks grouped by ban class — BEFORE score 31/80, BEFORE leak score 9. The theme decision (FE-363) deepens the identity engineers already recognise: dark navy + mono data voice, kept and given the full treatment — one token source (navy ramp, one signal accent, tabular numerals), a display/body/data type scale, dial 2 (a tool, not a story). The staged passes run whole-app in order; pass 4 gives every chart card its full state set, including a real empty state ("No events yet — events appear here once your product sends them") and a real error state ("Couldn't load this chart — check your connection and try again"). The signature element (FE-366) is the usage chart's own line, lifting out as a ribbon the user scrubs along the real timeline — the element IS the data, and removing it removes the ability to read change over time; it passes all four merge tests. The internals were used to understand the product (FE-369) — the team read the schema and the queries to know what the charts mean — and none of it surfaces: AFTER leak score 0, AFTER design score 71/80. Rejected, with reasons recorded: adopting a library theme whole (would erase a working, recognised identity to chase novelty), and keeping the custom cursor (heavy by measurement — FE-372).
