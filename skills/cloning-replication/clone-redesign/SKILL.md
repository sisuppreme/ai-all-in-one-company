# clone-redesign

## Metadata

- **Owner department:** D16 Cloning & Replication (CL)
- **Skill version:** 1.0.0
- **Last verified:** 2026-11-21
- **Sources:** https://playwright.dev/docs/test-snapshots ; https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/
- **Depends on:** clone-ethics (D14 gate), page-inventory, behavior-cloning
- **Feeds into:** fidelity-verification (behavior half only — see CL-150), handover

## When to use / Do NOT use

**The legal line: function may be cloned; protected expression may not be copied.** This skill operates entirely inside that line — CL-142's two-column split is its working form, and clone-ethics' LG-182, LG-186, and LG-187 govern throughout (CL-141) and are never re-decided here.

- **Use when:** an authorized engagement must rebuild a reference product's function — its flows, features, validation, states, and data behavior — as a competing or successor product with a completely original design, brand, and copy. The parity target is what the product *does*; the design target is zero resemblance in how it looks, reads, and brands. Typical cases: a competitor rebuild under clone-ethics ground LG-182(d), a white-label functional equivalent, or a client's functional re-platform where the old brand and look are being retired, not migrated.
- **Do NOT use when:** the rebuild must match the source's appearance (that is the standard clone-rebuild path: design-extraction tokens consumed as rebuild values, page-reconstruction, and fidelity-verification's pixel suite — this skill forbids all three), the operator owns the source's brand and is migrating it as-is (clone-ethics' explicit-reuse exception; use the standard path), no D14 clone-ethics authorization record exists (run clone-ethics first; this skill refuses to start), or only the behavior spec is needed with no build yet (behavior-cloning alone).
- **Boundary with rebrand-execution:** this skill builds the product *and* its original brand in one engagement (CL-146, CL-153) — the brand is created here, not changed here. Changing the identity of a product that already exists and is live — including a product this skill built, once it is live — is rebrand-execution's work, run on that product as its existing, live product. A redesign that keeps the existing brand is still this skill's build for function, design, and copy, but the brand itself is not redesigned: its surfaces are inventoried under rebrand-execution's discipline and marked `keep` (CL-702 to CL-704), and any later change to them is a rebrand, not part of this build.

## Rules

1. **CL-141 — Authorization precedes the redesign brief.** No function inventory or expression brief is written before the D14 clone-ethics authorization record exists, predates the first artifact, and names clone-redesign (function parity, original expression) in scope. Where the product will compete with the reference, the record states the LG-182 ground explicitly; LG-186 and LG-187 govern throughout and are never re-decided inside this skill.
2. **CL-142 — Every requirement lives in exactly one of two columns.** The redesign spec is a two-column document: the **function column** (flows, features, inputs, validation rules, state changes, network effects, error and empty states, edge cases) carries a parity obligation; the **expression column** (layout composition, visual system, typography, color, imagery, iconography, motion and animation, brand, naming, all copy) carries an originality obligation. An item that fits neither column is out of scope; an item claimed by both is split until each half sits in one column.
3. **CL-143 — The function column is sourced from behavior-cloning specs, never re-observed ad hoc.** Function entries cite the frozen behavior-cloning interaction specs (trigger, action, observed result) as their source. This skill does not record behavior itself: a missing or `unobserved` flow is routed back to behavior-cloning or carried as `unobserved` — it is never filled in from the builder's familiarity with the reference product. One further evidence class is admitted: `documented`. A function known from the vendor's own documentation (help center, API docs, changelog) but not directly observable enters the inventory cited to that documentation — the source and its capture date recorded in `fact-sheet.md` — and never with a behavior-spec ID: a documented claim is the vendor's statement, not an observation. In the two-column spec a `documented` function is carried as `unobserved`, with its documentation citation recorded in the divergence log; at acceptance (CL-150) it is dispositioned *designed* — built fresh from the documentation, in original expression — or first re-observed and re-classed through behavior-cloning. At acceptance, no function may remain in the `unobserved` state: each is dispositioned in the divergence log as designed (specified fresh as new product work and labeled *designed*, never *cloned*) or excluded with its reason.
4. **CL-144 — Design-extraction output is a negative reference, never a value source.** Where design-extraction has run, its token file and replace-list may be consulted only to know what to avoid and what must be replaced (per CL-051's replace-list). No extracted color, type, spacing, radius, shadow, or breakpoint value is copied, rounded, shifted, or "inspired-adjusted" into the redesign's token file; the redesign's tokens are authored fresh under CL-146.
5. **CL-145 — Functional necessity is the only expression exception, and it is narrow.** An expression element may resemble the reference only where the resemblance is dictated by the function itself — a standard control's conventional behavior, a legally required label, a data format — and each such case is entered in the divergence log with the functional reason. "Users expect it to look like that", familiarity, and conversion habit are not functional reasons.
6. **CL-146 — The expression system is authored before any page is built.** Before the first page build, the project commits an original design record: its own DTCG token file (color, type scale, spacing, radii, shadows, breakpoints), typeface choices with license status, imagery direction, and brand assets (name, logo, wordmark) created for this product. A page built before the design record exists is rework, not progress, because there is nothing yet to build it *in*.
7. **CL-147 — All copy is written from the function column, never from the reference's text.** Headings, labels beyond functional necessity, help text, error wording, empty-state text, marketing copy, and metadata are drafted from what the element *does* (its function-column entry), with the reference's copy closed during drafting. Paraphrase, synonym substitution, and sentence reordering of reference copy do not count as writing (see BAN-CL-073).
8. **CL-148 — Information architecture may move; flow steps may not silently change.** Navigation grouping, page composition, and visual hierarchy are expression and are redesigned freely. The sequence of user actions, required inputs, validation outcomes, and resulting state changes inside a flow are function: any deliberate functional difference from the reference (a step merged, a field dropped, a default changed) is a recorded functional deviation with a reason and an approver, never an unlogged side effect of the new layout.
9. **CL-149 — Layout signatures must differ measurably.** For each template, the redesign's composition differs from the reference's in at least the structural choices the design record names — grid structure, hero/first-viewport composition, navigation placement, and section ordering — except where CL-145 applies. "Same layout, new colors and fonts" is a reskin, not a redesign, and fails this rule however original the tokens are.
10. **CL-150 — Acceptance is behavior parity plus design distance, in that order.** The rebuild is accepted only when (a) the frozen behavior-cloning suite passes against it unmodified, exactly as in behavior-cloning's CL-092 — this skill changes nothing about that run; and (b) the design-distance gates of this skill pass (G-CL-072 to G-CL-074). fidelity-verification's pixel-similarity suite (G-CL-061) is **not applicable** to a clone-redesign: it is recorded as NOT APPLICABLE with this rule as the reason, never run-and-failed and never run-and-passed.
11. **CL-151 — Claims language matches the split.** Deliverables may claim "functionally equivalent to", "feature parity with", or "behavior verified against" the reference, each citing its behavior run. They never claim or imply visual, brand, or copy parity or resemblance, and never use the reference's name, logo, or screenshots in the rebuild's own marketing or product surfaces in a way that suggests endorsement or identity (the LG-187 side-by-side test is the check: a viewer must not be able to mistake one product for the other).
12. **CL-152 — The divergence log is the audit artifact.** Every CL-145 exception, every CL-148 functional deviation, every template's CL-149 structural differences, and the G-CL-061 NOT APPLICABLE disposition are recorded in one divergence log with dates and approvers. A difference that exists in the build but not in the log is treated as an undetected copy until proven otherwise.
13. **CL-153 — The new brand is cleared, not merely different.** Before the design record is committed, the new product's name, mark, and wordmark are searched against the reference's marks and protected-items list and against the trademark registers of the launch markets; the search and its result are recorded in the design record. A name or mark that is confusingly similar to the reference's — or that trades on the reference's identity or goodwill — fails this rule however different the pixels are, as does a name already held by a third party in a launch market. CL-151 governs what the deliverables *claim*; this rule governs what the product is *called*.
14. **CL-154 — Imagery and iconography are originated, never derived.** Every illustration, icon, and image in the redesign is created for this product, commissioned, or licensed, with its provenance (creator or license, date) recorded in the design record or the asset manifest. Reference imagery is never traced, redrawn, vectorized, recolored, or imitated closely enough in style, composition, and subject together that a side-by-side viewer would recognize the derivation (the LG-187 test applied to images). Matching the reference's illustration *subjects* is unavoidable where the function matches — an invoice icon is an invoice icon; matching its rendering style and composition is copying.

## BAN list

- **BAN-CL-071 — Extracted tokens as rebuild values.** Banned: using design-extraction's sampled values — exactly, rounded, hue-shifted, or renamed — as the redesign's colors, type, spacing, radii, shadows, or breakpoints. Defeats: DET-CRWL-009. Bad: the reference's sampled `#1f4fd8` ships as the redesign's primary `#2050da` "because it's basically a different blue", with the spacing scale copied at a 1.0 ratio. Instead: author the token file fresh from the design record under CL-146, and let G-CL-072 diff it against the extracted set. Severity: BLOCK.
- **BAN-CL-072 — The reskin presented as a redesign.** Banned: keeping the reference's layout composition, section order, and navigation placement while changing only colors, fonts, and imagery, and delivering it as an original design. Defeats: DET-NONE — no DET parameter names design-similarity as its signal; governed by CL-149 and LG-187. Bad: every page of the rebuild overlays the reference's wireframe almost exactly; only the palette and logo differ. Instead: change the structural choices per template and record them under CL-149 before build. Severity: BLOCK.
- **BAN-CL-073 — Paraphrase-laundered copy.** Banned: producing the rebuild's copy by editing the reference's text — synonym swaps, reordered clauses, translated-and-back wording — instead of writing from the function. Defeats: DET-CRWL-009. Bad: the reference's pricing headline is rewritten word-by-word into a near-identical sentence and shipped as "original copy". Instead: draft with the reference's copy closed, from the function-column entry, under CL-147; G-CL-073's text-overlap scan is the check. Severity: BLOCK.
- **BAN-CL-074 — Pixel-parity tuning in either direction.** Banned: running fidelity-verification's pixel suite on a clone-redesign to chase a similarity score — raising it ("closer is safer") or engineering against a screenshot overlay to hit a distance number. Defeats: DET-NONE — no DET parameter names this signal; governed by CL-150. Bad: the builder overlays reference screenshots during the build to confirm the pages "look different enough, but not too different". Instead: record G-CL-061 as NOT APPLICABLE under CL-150 and judge distance by the token, copy, and layout checks (G-CL-072 to G-CL-074). Severity: BLOCK.
- **BAN-CL-075 — Parity claimed from the feature list.** Banned: claiming functional equivalence because the rebuild's feature list matches the reference's feature list, without the frozen behavior suite having run and passed. Defeats: DET-CRWL-002. Bad: the handover states "full feature parity with the reference" because both products list search, filters, and checkout — while the rebuild's filter validation and double-submit behavior were never tested against the specs. Instead: run the unmodified frozen suite under CL-150(a) and cite that run for every parity claim. Severity: BLOCK.

## Gates

- **G-CL-071 — Two-column spec completeness (automated).** Verifies: CL-142, CL-143. Check: script parses the redesign spec — every function-column entry cites a behavior-cloning spec ID or carries an `unobserved` marker; every `documented` entry (CL-143) carries its full documentation citation — the source named, its capture date present in `fact-sheet.md`, and the citation recorded in the divergence log — and cites no behavior-spec ID; and every inventoried page/flow from page-inventory appears in exactly one column assignment. Pass: zero uncited function entries, zero `documented` entries with an incomplete citation, zero unassigned inventory items. Fail: block the build; missing function evidence routes back to behavior-cloning, and a `documented` entry without its citation is treated as `unobserved` until the citation exists. Recorded in: progress.md.
- **G-CL-072 — Token distance diff (automated).** Verifies: CL-144, CL-146. Check: script compares the redesign's DTCG token file against the design-extraction token file (where one exists): no color within one hex step per channel of an extracted color, no identical spacing/radius/breakpoint value outside values the divergence log justifies under CL-145, and no extracted font stack present. Where no extraction ran, the check instead asserts the design record predates the first built page (commit timestamps). Pass: zero unjustified collisions. Fail: block shipment; colliding values are re-authored, not nudged. Recorded in: progress.md.
- **G-CL-073 — Copy-overlap scan (automated).** Verifies: CL-147. Check: n-gram overlap scan of the rebuild's rendered text against the reference's captured copy (the same capture set behavior-cloning and clone-ethics already hold): any shared sequence beyond functional labels, legally required wording, and proper nouns logged under CL-145 fails. Pass: zero unlogged overlaps. Fail: block shipment; flagged copy is rewritten from the function column with the reference closed. Recorded in: progress.md.
- **G-CL-074 — Layout-signature review (manual).** Verifies: CL-149, CL-152. Check: a reviewer places each template's wireframe (structure only — blocks, order, navigation placement, no styling) beside the reference's and confirms the design record's named structural differences are present, and that every remaining structural resemblance has a CL-145 entry in the divergence log. Pass: every template differs structurally as recorded, with no unlogged resemblance. Fail: block sign-off; the template returns to design, not to styling tweaks. Recorded in: progress.md.
- **G-CL-075 — Split acceptance record (manual).** Verifies: CL-150, CL-151. Check: review the acceptance record before handover — it must contain (a) the frozen behavior suite's passing run ID, hashes matching the frozen set; (b) passing results for G-CL-072, G-CL-073, and G-CL-074; (c) the G-CL-061 NOT APPLICABLE entry with its CL-150 reason; and (d) a claims sweep of the deliverables showing behavior-parity language only, with no visual or brand resemblance claim; and (e) the divergence log showing zero functions left in the `unobserved` state — each dispositioned as designed or excluded under CL-143. Pass: all five elements present. Fail: block handover until the record is complete. Recorded in: progress.md.
- **G-CL-076 — Brand and imagery clearance review (manual).** Verifies: CL-153, CL-154. Check: a reviewer confirms (a) the brand-clearance record exists in the design record — the CL-153 search of the new name and mark against the reference's marks and the launch markets' trademark registers, dated before the design record was committed, with no confusing similarity found; and (b) every shipped illustration, icon, and image carries a provenance entry (created, commissioned, or licensed, with source and date), and a side-by-side comparison of the shipped imagery against the reference's captured imagery shows no traced, redrawn, or style-derived item — the derivation a hash comparison cannot see. Pass: clearance record complete and zero derived imagery. Fail: block handover; an unclearable name returns to the design record, and derived imagery is replaced with originated work. Recorded in: progress.md.

## Anti-patterns

- **Muscle-memory rebuild.** The builder knows the reference product well and reproduces its screens from familiarity while believing they are designing fresh. Catch it: build from the function column and the design record with reference screenshots closed; open the reference only inside G-CL-074's review.
- **Originality at the edges.** The marketing pages are genuinely redesigned, but the app screens — forms, tables, settings — quietly follow the reference's layout because "those are just functional". Catch it: G-CL-074 covers every template, including utility screens; function explains a control's behavior, not its composition.
- **Deviation amnesia.** Deliberate functional improvements made during the redesign (a merged step, a better default) are real and defensible — but unlogged, so the behavior suite's failures look like bugs and get "fixed" back. Catch it: log the CL-148 deviation before changing the flow, so the suite failure and the decision meet in the record.
- **Distance theater.** The design is made different in ways users feel as worse — navigation moved solely to be unlike the reference, conventions broken for distance's sake. Catch it: CL-149 requires structural difference, not perversity; the design record should state the redesign's own rationale for each structural choice, not merely its difference from the reference.

## Recall anchors

- Clone what it does; design nothing like how it looks — the new brand is cleared, not just different, and every shipped image has a provenance.
- Two columns: function owes parity, expression owes originality — nothing sits in both.
- Extracted tokens are a map of what to avoid, never a palette to reuse.
- Copy is written with the reference closed, from the function alone.
- Acceptance is the behavior suite plus design distance — the pixel suite does not run here.

## Checklist

- [ ] The clone-ethics authorization record exists, predates the brief, and names clone-redesign in scope (CL-141).
- [ ] Every spec item sits in exactly one column; every function entry cites a behavior-cloning spec or is marked `unobserved` (CL-142, CL-143, G-CL-071).
- [ ] An original design record — tokens, typefaces, brand assets — is committed before the first page build (CL-146).
- [ ] No extracted design value appears in the redesign's tokens without a CL-145 log entry (CL-144, G-CL-072).
- [ ] All copy was drafted from the function column with the reference's text closed (CL-147, G-CL-073).
- [ ] Every template's structural differences and every functional deviation are in the divergence log with an approver (CL-148, CL-149, CL-152, G-CL-074).
- [ ] The frozen behavior suite passes unmodified, and G-CL-061 is recorded NOT APPLICABLE with its reason (CL-150, G-CL-075).
- [ ] Deliverables claim behavior parity only — no visual, brand, or copy resemblance claim anywhere (CL-151).
- [ ] The new name and mark are cleared — searched against the reference's marks and the launch markets' trademark registers, with the result recorded in the design record (CL-153, G-CL-076).
- [ ] Every shipped image and icon has a provenance entry, and none is traced, redrawn, or style-derived from the reference's imagery (CL-154, G-CL-076).
