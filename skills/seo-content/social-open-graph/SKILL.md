## When to use / Do NOT use

- **Use when:** a site launches, a page template is built or changed, branding changes, or a shared link previews the wrong title, description, or image. This skill owns the Open Graph and Twitter Card tags every public page emits.
- **Do NOT use when:** the question is what the page itself says (copywriting, on-page-seo), what its JSON-LD declares (structured-data), or whether the page is indexable (technical-seo). Never use it to promise share traffic: platforms render the tags; they do not guarantee distribution.

## Rules

1. **CO-221 — The four required properties, on every public page.** Every public page emits `og:title`, `og:type`, `og:image`, and `og:url`, plus `og:description` and `og:site_name`. A page missing any required property is a defect, not a style choice.
2. **CO-222 — og:url is the page's canonical URL.** og:url equals the canonical URL technical-seo assigns the page. A site-wide homepage og:url on interior pages is a defect (DET-CON-023).
3. **CO-223 — og:title and og:description are per-page.** Both are generated from the page's own title and topic and match what the link actually opens. Identical og:title or og:description across pages with different destinations is a defect.
4. **CO-224 — og:image is absolute and page-appropriate.** og:image is an absolute URL (never a relative path a crawler cannot resolve) pointing to an image that represents this page, at full share size — the protocol's recommended 1200×630. The homepage logo is never the og:image for every page.
5. **CO-225 — The image fallback is a compromise, not the design.** Only og:image may fall back to a site-wide default share image, and that fallback is recorded as a known compromise. og:title, og:description, and og:url never fall back to site-wide values.
6. **CO-226 — og:site_name is this site's own name.** og:site_name carries the site's current name from the fact sheet, on every page. A scaffold's or another site's name in og:site_name is a defect.
7. **CO-227 — og:type matches the content, with its properties.** Pages use the og:type that fits (website for general pages, article for posts, product for product pages), and type-specific properties are emitted where they apply — article:published_time and article:author on posts.
8. **CO-228 — Twitter Card tags mirror the OG values.** twitter:card, twitter:title, twitter:description, and twitter:image are emitted and carry the same per-page values as their OG counterparts; twitter:card is summary_large_image wherever og:image meets the large-image size. Two metadata systems describing one page never disagree.
9. **CO-229 — Tags are generated in the page template.** OG and Twitter tags are produced by the page template from the page's own data — the same source that renders the visible title and description. Hand-edited per-page tag blocks and tags pasted from a scaffold or another site are defects.
10. **CO-230 — Share images are real assets.** Every og:image URL returns HTTP 200 and serves the image the tags claim. A purpose-built share image is produced for each page type; a stretched logo, a placeholder graphic, or a stock photo presented as the product is a defect.
11. **CO-231 — No private or gated page gets public card promises.** Pages behind authentication, staging hosts, and noindex pages do not emit OG tags describing them as public content, and production tags never point at staging URLs or staging images.
12. **CO-232 — Debuggers re-run after template or branding changes.** Social platforms cache previews aggressively, so after any template, branding, or share-image change, the home, article, and product templates are re-run through the platform debuggers to force fresh scrapes. A fix that is never re-scraped is not live.

## BAN list

- **BAN-CO-111 — Site-wide homepage og:url.** Banned: emitting the homepage URL as og:url on every page. Defeats: DET-CON-023. Bad: `/pricing`, `/blog/setup-guide`, and `/about` all carry `<meta property="og:url" content="https://example.com/">`, so every share attributes to and previews as the homepage. Instead: og:url is each page's own canonical URL, generated by the template (CO-222). Severity: BLOCK.
- **BAN-CO-112 — One og:title and og:description for the whole site.** Banned: a single global title/description pair in the social tags regardless of destination. Defeats: DET-CON-023. Bad: every page shares with og:title "Example — Do More With Less" and the homepage description, including the changelog and a support article. Instead: og:title and og:description are generated per page from that page's title and topic (CO-223). Severity: BLOCK.
- **BAN-CO-113 — Homepage logo as every page's og:image.** Banned: pointing og:image at the site logo or one generic brand graphic for all pages. Defeats: DET-CON-023. Bad: a detailed pricing page and a photo-heavy case study both preview as the company logo on a white background. Instead: each page type gets a purpose-built share image representing its content; only a recorded fallback may reuse the default image (CO-224, CO-225). Severity: BLOCK.
- **BAN-CO-114 — Another site's identity in the tags.** Banned: og:site_name, og:title suffixes, or image URLs copied from a scaffold, theme demo, or another site and never replaced. Defeats: DET-CON-023. Bad: og:site_name reads "Acme Starter Kit" and og:image resolves on the theme vendor's domain, months after launch. Instead: site_name and branding come from this site's fact sheet, and all tag assets are served from this site's own domain (CO-226, CO-229). Severity: BLOCK.
- **BAN-CO-115 — Relative or broken og:image.** Banned: og:image as a relative path, a staging URL, or a URL that does not return the claimed image. Defeats: DET-CON-023. Bad: `<meta property="og:image" content="/images/share.png">` on production pages, so crawlers cannot resolve it and shares render with no image. Instead: og:image is an absolute production URL verified to return HTTP 200 with the intended image (CO-224, CO-230). Severity: BLOCK.

## Gates

- **G-CO-111 — Site-wide tag dump diff.** Verifies: CO-221, CO-222, CO-223, CO-226. Check: automated — crawl every public URL, extract all OG and Twitter tags, and diff: og:url must equal the page's canonical URL, og:title/og:description must match the page's own title/topic with no cross-page duplicates across different destinations, og:site_name must equal the current brand name, and all four required properties must be present. Pass: zero mismatches. Fail: block shipment of the affected templates. Recorded in: progress.md.
- **G-CO-112 — og:image resolution and size check.** Verifies: CO-224, CO-225, CO-230. Check: automated — request every distinct og:image URL; assert absolute URL, HTTP 200, image content type, and dimensions of 1200×630; flag any image reused across pages outside the recorded fallback list. No-image disposition: a page with no image assets (a text-only page) may ship with no og:image only when that absence is recorded as a deliberate disposition in progress.md, naming the page and the reason; an unrecorded absence is a failure, not a disposition. Pass: every og:image resolves at full share size and reuse matches the fallback record, and every page without one carries the recorded no-image disposition. Fail: fix the asset or the template and re-run. Recorded in: progress.md.
- **G-CO-113 — Platform debugger pass.** Verifies: CO-227, CO-228, CO-232. Check: manual — run the production home, article, and product URLs through the Meta Sharing Debugger and the X/Twitter card validator; confirm the rendered preview shows the page's own title, description, and image, and re-scrape after any template or branding change. Pass: all three templates preview correctly with current branding. Fail: correct the tags and force a re-scrape before launch sign-off. Recorded in: progress.md.
- **G-CO-114 — Template generation audit.** Verifies: CO-229, CO-231. Check: automated grep plus manual review — search templates and rendered output for hardcoded og: tags, foreign domains, and staging hosts; confirm tags are emitted from page data and that gated/noindex pages carry no public card tags. Pass: no hardcoded or foreign tag values found; tags trace to the page template. Fail: move generation into the template and re-run G-CO-111. Recorded in: progress.md.

## Anti-patterns

- **The set-and-forget card.** Tags were correct at launch, then a redesign changed titles, branding, and images while the OG tags kept describing the old site. Catch it: any template or branding change without a debugger re-run (CO-232) means the cards are stale by default.
- **Checking one page and declaring the site done.** The homepage previews perfectly, so nobody samples an article, a product page, or a deep docs page — where the template defaults actually live. Catch it: verification samples every page type, never just the homepage.
- **The plugin shrug.** A metadata plugin or framework default is installed and trusted, and its output is never read. Catch it: dump the rendered tags (G-CO-111) — if nobody has seen the actual values, they are unverified, whatever generated them.
- **Designing the share image last.** Pages ship with whatever image was nearest — a screenshot with a browser chrome edge, a logo stretched to 1200×630. Catch it: share images are named deliverables per page type (CO-230), reviewed like any other visual asset.

## Recall anchors

- og:url is the page's canonical URL — never the homepage site-wide.
- Title and description are per-page; only the image may fall back.
- og:image: absolute URL, page-appropriate, 1200×630.
- og:site_name is this site's own current name.
- Platforms cache previews — re-scrape after every template or branding change.

## Checklist

- [ ] Every public page emits og:title, og:type, og:image, og:url, og:description, and og:site_name (CO-221).
- [ ] Tag dump diff is clean: og:url equals canonical, no cross-page title/description duplicates (G-CO-111).
- [ ] Every og:image is absolute, returns 200, and is 1200×630 (G-CO-112).
- [ ] og:site_name matches the current brand name from the fact sheet (CO-226).
- [ ] Twitter Card tags mirror the OG values (CO-228).
- [ ] Home, article, and product templates pass the platform debuggers with current branding (G-CO-113).
- [ ] No hardcoded, foreign-domain, or staging values in any tag (G-CO-114).
