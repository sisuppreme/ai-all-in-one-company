# Example 3 — "New and latest" forever

Demonstrates: PM-028 — write timelessly; time-anchored words never stand in for a version number.

## Before

> ## Dashboards
>
> Our new dashboard now gives you a currently-updated view of your projects. The latest release adds real-time charts, and a brand-new sharing panel is coming soon.
>
> To open the new dashboard, click **Home**. Existing users will be migrated to the new experience shortly.

Nothing on the page says which release "the latest" is, what "new" replaced, or when "soon" and "shortly" resolve. Two versions later the page is still announcing the same "new" dashboard — and quietly lying about the migration.

## After

> ## Dashboards
>
> The dashboard shows each project's status, recent activity, and open tasks. Charts refresh as data changes.
>
> To open the dashboard, click **Home**.
>
> Version notes: the dashboard replaced the project list as the home view in 2.0. The sharing panel was added in 2.3; see [Sharing a dashboard](../how-to/share-dashboard.md).

The evergreen page states only what is true now, in the present tense. The dated facts moved into version notes, where a reader can tell exactly which release each statement belongs to — and the freshness gate can retire them on schedule.
