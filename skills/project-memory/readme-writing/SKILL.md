## When to use / Do NOT use

- **Use when:** creating a project README, replacing scaffold output at project start, or changing anything the README states — what the project is, its status, its version, or how to run it.
- **Do NOT use when:** writing the depth the README points to — tutorials, how-tos, and reference belong to documentation-writing; operating procedures belong to runbook-writing. The README is the front door and index, never the manual.

## Rules

1. **PM-041 — Fixed front-door order.** The README carries, in this order: project name, one line stating what it is, who it is for, current status with a date, the quickstart, and a link index into the doc set (ARCHITECTURE, runbook, CHANGELOG, DECISIONS). A section that fits none of these moves behind a link.
2. **PM-042 — No boilerplate survives.** Every line of generator or template output (framework welcome text, default badges, placeholder sections) is replaced with project content or deleted before the README first ships; "we will fill this in later" is not a shipped state.
3. **PM-043 — Quickstart executed verbatim.** Every quickstart command is run exactly as written, in order, in a clean checkout, before the README ships and after any change to it. A command that fails, or needs a step the README omits, is a README bug fixed in the README or the project — never explained away.
4. **PM-044 — Badges report real systems only.** A badge is present only if it is generated by a live system: CI status from the actual pipeline, version from the project's version source of truth, coverage from the actual test run. Hand-written or static shields claiming a state nobody measured are prohibited.
5. **PM-045 — Link, never duplicate.** Each mandated file is linked exactly once from the index; its content is never copied into the README. Every fact has one canonical home, and the README's copy of a fact is a link to that home.
6. **PM-046 — Every claim verified against the system.** Features, commands, flags, ports, and requirements named in the README are checked against the actual project before shipping. A feature that does not exist yet is labeled with its planned status and date, or omitted.
7. **PM-047 — Status is dated and current.** The status line carries an ISO 8601 date and is re-verified whenever the README changes; a stated version must equal the version source of truth (git tag or package version). An undated status is treated as stale.
8. **PM-048 — One-sitting length.** The README is short enough to read in one sitting; when a draft grows past what a new reader can scan in a few minutes, the overflow moves into the doc set and the README keeps the link.
9. **PM-049 — Shortest path to running.** The quickstart is the minimum sequence from clone to a running project, with prerequisites (runtime versions, required services, env files) listed before the first command — never discovered mid-sequence.
10. **PM-050 — README changes ride with the change.** Any change that alters what the README states (a renamed command, a new prerequisite, a status change) updates the README in the same change; a merged change that leaves the README wrong is incomplete.
11. **PM-051 — Every link resolves.** Relative links point at files that exist in the repo; external links are checked with the link checker. A link to a planned-but-absent file is removed until the file exists.
12. **PM-052 — Names match the record.** The project name, product names, and terminology are spelled exactly as in the project's fact sheet and word list, in the title, body, and badge URLs alike.

## BAN list

- **BAN-PM-021 — Scaffold README shipped.** Banned: publishing the generator's default README (framework welcome text, "getting started" boilerplate, sample badges) as the project's front door. Defeats: DET-CON-002. Bad: the repo ships the Vite default README — "This template provides a minimal setup to get React working in Vite" — for a client billing tool. Instead: replace or delete every scaffold line at project start (PM-042); the first shipped README is written for this project. Severity: BLOCK.
- **BAN-PM-022 — Decorative badges.** Banned: static or hand-made badges asserting build status, coverage, or version that no live system produced. Defeats: DET-CON-012. Bad: a green "build: passing" shield pasted from shields.io into a repo with no CI configured. Instead: wire the badge to the real pipeline's badge URL, or remove it until the system exists (PM-044). Severity: BLOCK.
- **BAN-PM-023 — Untested quickstart.** Banned: shipping quickstart commands that were written from memory and never executed in a clean checkout. Defeats: DET-CON-015. Bad: the README says `npm run dev` but the package defines only `start`; the README and the project contradict each other on the first command a reader runs. Instead: run every command verbatim in a clean checkout and fix the mismatch at its source before shipping (PM-043). Severity: BLOCK.
- **BAN-PM-024 — Features that do not exist.** Banned: describing planned, imagined, or removed features in the README as current capability. Defeats: DET-CON-028. Bad: "Exports reports to PDF and Slack" in the feature list of a project with no export code and no Slack integration. Instead: verify each named feature against the running system (PM-046); label planned work as planned, with a date, or cut it. Severity: BLOCK.
- **BAN-PM-025 — Fossil status line.** Banned: a status or version statement left standing after it stops being true ("currently in alpha", a version two releases old, a roadmap dated last year). Defeats: DET-CON-018. Bad: the README announces "v0.2 — early alpha, expect breaking changes" while the repo is tagged v1.4. Instead: date the status, re-verify it on every README change, and match the version source of truth (PM-047). Severity: WARN.

## Gates

- **G-PM-021 — Quickstart execution.** Verifies: PM-043, PM-049. Check: automated — in a clean clone, run the project's `scripts/readme-quickstart-check.sh`, which extracts the fenced shell blocks under the README's quickstart heading and executes them in order. Pass: every command exits 0 and the final state is the running project. Fail: block shipment; fix the README or the project. Recorded in: progress.md.
- **G-PM-022 — Boilerplate and marker scan.** Verifies: PM-042. Check: automated — `grep -niE 'create-react-app|create vite|this template provides|getting started with .* framework|TODO|FIXME|lorem|description here' README.md` plus a diff of the README's first heading against the scaffold default. Pass: zero hits. Fail: block shipment until each hit is replaced or deleted. Recorded in: progress.md.
- **G-PM-023 — Link integrity.** Verifies: PM-045, PM-051. Check: automated — `lychee README.md` for all links, and a manifest check that each mandated file for the project type appears as a link target. Pass: zero broken links and every mandated file linked exactly once. Fail: block shipment. Recorded in: progress.md.
- **G-PM-024 — Fresh-reader test.** Verifies: PM-041, PM-048. Check: manual — a reader who has never seen the project reads the README once and states what the project is, who it is for, its current status, and the exact steps to run it. Pass: all four answers correct from the README alone. Fail: rewrite the failing section and re-test. Recorded in: progress.md.

## Anti-patterns

- **The link farm with no door.** An index of links and nothing else — no statement of what the project is or who it serves. Catch it: cover the links; if the remaining text cannot answer "what is this?", PM-041 has failed even though every link works.
- **The screenshot hero.** A banner image or demo GIF carrying the explanation while the text says nothing checkable. Catch it: read the README with images disabled; every claim must survive in text.
- **The buried quickstart.** Forty lines of philosophy, architecture, and history before the first runnable command. Catch it: the quickstart must appear before any section a first-time reader does not need to run the project.
- **The changelog dump.** Release history pasted into the README to make it look maintained, duplicating CHANGELOG.md until the two disagree. Catch it: history lives in CHANGELOG.md; the README links to it (PM-045).

## Recall anchors

- Front door and index — never the manual.
- If a command is printed, it was run, verbatim, in a clean checkout.
- A badge is a report from a live system or it is deleted.
- Every fact lives in one file; the README holds the link.
- Undated status is stale status.

## Checklist

- [ ] Sections follow the PM-041 order: what, who, dated status, quickstart, link index.
- [ ] No scaffold or template text remains (G-PM-022 clean).
- [ ] Quickstart executed verbatim in a clean checkout, all exit 0 (G-PM-021).
- [ ] Every badge is generated by a real system; version matches the source of truth (PM-044, PM-047).
- [ ] Every mandated file linked exactly once; no content duplicated from them (G-PM-023).
- [ ] Every named feature, command, and requirement verified against the actual project (PM-046).
- [ ] Fresh-reader test passed and recorded (G-PM-024).
