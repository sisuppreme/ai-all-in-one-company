# Contract: D16 ↔ D3 — Clone Design Sync

- **Backbone link:** #11 of 13 (MASTER_BRIEF.md §3.11)
- **Link type:** SHARES
- **Owner departments:** D16 Cloning & Replication and D3 Frontend, Design & Motion (co-owners)
- **Liaisons:** D16 Design system extractors ↔ D3 Design system builders
- **Skills on each side:** design-extraction, page-reconstruction (D16) ↔ design-tokens, design-system (D3)

## Artifact that passes

`CLONE_DESIGN_SYSTEM.md` with its token file — the design system extracted from
the authorized source: colors, type scale, spacing, radii, elevation, and
component patterns, in DTCG token format. D16 extracts it; D3's token discipline
governs its shape; the rebuild (D16 page-reconstruction, built with D3 skills)
consumes it unchanged.

## Format

DTCG-format token JSON (the same format design-tokens mandates: $value, $type,
$description per token) plus a Markdown pattern inventory. Values are measured
from the source (computed styles, captures), never eyeballed or invented;
unobservable values are marked as designed-not-cloned.

## When it passes

After design-extraction completes and before page-reconstruction starts. Any
re-extraction (source changed, capture set re-frozen) re-issues the artifact
with a new version and date.

## Acceptance test (how the receiver verifies)

**Joint gate — design-sync.** The rebuild's token file is diffed against
CLONE_DESIGN_SYSTEM.md: every token value in the rebuild traces to an extracted
value or to an explicit designed-not-cloned note. A value that appears in the
rebuild with no extraction source is a defect — it means the rebuild invented
a design instead of syncing to the extracted one.

## If the test fails

Reconstruction pauses on the affected pages. The token is either corrected to
the extracted value or formally recorded as a deliberate deviation with the
reason — silent drift between extraction and rebuild is exactly the failure
this link exists to prevent.
