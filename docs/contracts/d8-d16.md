- **Consumer department:** D16 Cloning & Replication
- **Liaisons:** D8 Visual & accessibility testers ↔ D16 Reconstruction designers
- **Skills on each side:** visual-regression, qa-gates (D8) → fidelity-verification, page-reconstruction (D16)

## Artifact that passes

The fidelity report: per-page comparison results of the rebuild against the
frozen source capture set — viewports used, similarity scores per page (not
only an aggregate), masked regions and why, and the accepted-deviation records
for every difference that remains.

## Format

Markdown report generated from the comparison run, with the capture set's
freeze date and the pre-committed pass bar (≥ 95% per fidelity-verification
CL-122, with per-page vs aggregate scoring and masking rules committed before
the first run — never adjusted after seeing results).

## When it passes

At the end of every reconstruction batch, and as the release gate for the
clone as a whole. The capture set is frozen before the first comparison;
re-freezing it is a versioned event with a reason, not a quiet refresh.

## Acceptance test (how the receiver verifies)

**Joint gate — fidelity.** D8 re-runs the comparison independently against
the frozen capture set and confirms the report's numbers reproduce. Deviation
records are checked individually: each names the difference, the reason, and
the approver. Regenerating a baseline so the rebuild passes is banned
outright (BAN-CL-062) — the source baseline stays, and the deviation record
carries the difference.

## If the test fails

The affected pages return to page-reconstruction. A page that cannot reach
the bar is shipped only with an accepted-deviation record the user can see —
an unfaithful page presented as a verified copy is a Real Content Rule
violation, not a QA miss.
