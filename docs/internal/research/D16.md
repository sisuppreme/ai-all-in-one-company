# D16 — Cloning & Replication: Phase 2 Research

Input to Phase 3 skill drafting for the 7 D16 skills: `site-discovery`, `page-inventory`, `design-extraction`, `asset-harvesting`, `behavior-cloning`, `page-reconstruction`, `fidelity-verification`. The 8th catalog skill, `clone-ethics`, belongs to D14; D16 consumes it as a gate, and the handoff points are marked **[→ D14]** throughout.

## 1. Department standard

Professional site migration/rebuild practice today runs as an evidence pipeline, not a screenshot exercise:

1. **Inventory before rebuild.** The URL set is built from at least four independent sources — a rendered crawl, the XML sitemap(s), analytics/Search Console top pages, and the Wayback CDX index — and reconciled before any page is built. Migration practice treats the merged inventory plus a saved pre-launch crawl as the baseline every later comparison runs against (Screaming Frog crawl-compare and list-mode workflows are the common tooling pattern). Sources: https://guestpost.uk/screaming-frog/ ; http://umatechnology.org/best-seo-site-migration-monitoring-tools-for-redirects-crawling-and-indexing/
2. **Archive-grade capture.** Captures are stored as WARC records (ISO 28500, maintained by the IIPC) so every page and asset keeps its request/response provenance and can be replayed offline. Browser-driven crawlers (Webrecorder's Browsertrix Crawler, built on Puppeteer/Chrome with pywb) are the current standard for JavaScript-heavy sites because HTTP-only crawlers such as Heritrix miss rendered content; output is WARC, optionally packaged as WACZ. Sources: https://github.com/iipc/warc-specifications/blob/master/specifications/warc-format/warc-1.1/index.md ; https://webrecorder.net/blog/2021-02-22-introducing-browsertrix-crawler/ ; https://library.unt.edu/digital-projects-unit/web-archiving/software-processes/
3. **Design-system extraction, not per-page styling.** Computed styles are sampled across pages and states, clustered into tokens, and exported in the W3C Design Tokens format (DTCG 2025.10: `$value`, `$type`, groups, aliases); Style Dictionary or an equivalent compiler turns the token file into CSS variables/JS so the rebuild consumes values from one source. Sources: https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/ ; https://backlight.dev/docs/style-dictionary
4. **Fidelity as a measured gate.** Source and rebuild are screenshotted in the same browser engine at agreed viewports and pixel-diffed against committed golden baselines (Playwright visual comparisons emit expected/actual/diff images); the OmniForge bar is ≥95% pixel similarity on key viewports, with behavior verified by replaying recorded interaction tests. Source: https://playwright.dev/docs/test-snapshots
5. **Crawl etiquette is protocol, not courtesy.** Crawlers identify themselves and honor the Robots Exclusion Protocol (RFC 9309); RFC 9309 itself states robots rules "are not a form of access authorization," so a missing Disallow is never treated as permission. Source: https://www.rfc-editor.org/rfc/rfc9309.html

## 2. Failure modes this department prevents

Each item is the slop pattern named in PROJECT_ANATOMY.md Part 10; the skill in brackets is what blocks it.

- **Site discovery:** crawling only the links on the home page and declaring the site "fully mapped"; crawling paths robots.txt disallows. Orphan, archived-only, and JS-routed pages are silently dropped. [`site-discovery`]
- **Page inventory:** an inventory generated from the navigation menu alone, with blog posts, landing pages, and utility pages missing, presented as "all pages." Completeness becomes unprovable. [`page-inventory`]
- **Design extraction:** inventing a plausible palette, substituting a similar-looking font, hardcoding hex values per page. Pages look close individually and drift in aggregate. [`design-extraction`]
- **Asset harvesting:** bulk-downloading a competitor's photo library and shipping it unchanged; hotlinking the source site's CDN so the clone breaks when the original changes. [`asset-harvesting`]
- **Behaviour cloning:** rebuilding appearance from screenshots and declaring interactive elements "working" without clicking them; submit buttons that only show a success message. [`behavior-cloning`]
- **Page reconstruction:** fabricating a plausible dashboard from generic patterns and labeling it a "verified clone" of a page nobody has ever seen. [`page-reconstruction`]
- **Fidelity verification:** eyeballing two screenshots and reporting "pixel-perfect"; quietly regenerating baselines so a failing comparison turns green. [`fidelity-verification`]
- **Clone ethics:** cloning a live brand end to end — logo, copy, photography kept — and calling it a template; scraping behind a login with borrowed credentials. [`clone-ethics`, D14-owned; D16 enforces it as a pre-crawl gate]

## 3. Per-skill research notes

### site-discovery

**Core method.** Establish the target's full URL space before anything is built. Fetch `robots.txt` and the sitemap index first; run a browser-rendered crawl from the home page so JS-rendered links resolve; extract route manifests from JS bundles to expose client-side routes no anchor points to; query the Wayback CDX API with `matchType=domain` (or `prefix` per host) to enumerate historical captures, including pages the live site no longer serves. Deliverable is three lists — live crawl, sitemap, CDX — with a reconciliation note for every difference.

**Key rules.**
- No crawl starts before the D14 authorization record exists and predates the first crawl log entry. **[→ D14]**
- The crawler sends an identifying user-agent and obeys robots.txt Disallow rules and crawl-delay; a disallowed path is recorded as "excluded by robots," never fetched.
- Discovery scope is hosts and URL spaces, not content copying: nothing discovered here licenses reusing the target's copy, images, or marks.
- Never authenticate, borrow credentials, or route around a login/paywall to "complete" discovery; gated spaces are recorded as gated.

**Verification gates.**
- *Automatable:* script diffs the three URL lists (crawl vs. sitemap vs. CDX `matchType=domain`); gate fails if any URL is unexplained.
- *Automatable:* crawl log is grepped against the robots.txt Disallow set; any match fails the gate.
- Manual: spot-check 5 JS-bundle routes against the discovered list.

**Ethics constraints (binding).** Written authorization required before the first request; robots.txt obeyed in full; discovery never copies trademarks or copyrighted assets (it records URLs only); no auth or paywall bypass under any framing.

**Sources.** Wayback CDX Server API — https://github.com/internetarchive/wayback/blob/master/wayback-cdx-server/README.md ; RFC 9309 — https://www.rfc-editor.org/rfc/rfc9309.html

### page-inventory

**Core method.** Merge crawl output, sitemap entries, analytics top pages, and CDX records into one table; deduplicate and canonicalize (trailing slash, query parameters, casing, redirect sources resolved to targets). Cluster rows by DOM structure into templates so shared layouts are built once. Each row carries: canonical URL, page type, template ID, component set, HTTP status, last capture date, and a provenance flag — `public`, `archived-only`, or `inferred`. The client signs off the in-scope count before reconstruction starts; that count is the scope contract for the whole engagement.

**Key rules.**
- One row per canonical page; redirect sources are attributes of their target row, never rows themselves (Sitemaps-protocol discipline).
- No row is deleted silently: out-of-scope rows stay in the table with an exclusion reason, so "missing" is always distinguishable from "excluded."
- Inventory is built only from authorized discovery output; it inherits the discovery crawl's robots.txt compliance and must not be extended by fetching disallowed or gated URLs.
- The inventory records provenance and rights-relevant facts (e.g., pages whose assets are third-party) but never embeds the target's copyrighted text or imagery as reusable content.

**Verification gates.**
- *Automatable:* row count equals the reconciled discovery count from `site-discovery`; mismatch fails the gate.
- *Automatable:* duplicate-canonical check — canonicalized URLs must be unique across rows.
- Manual: fetch a random 10% sample of rows and confirm URL, status, and template label against the live or archived page.

**Ethics constraints (binding).** Authorization record must exist before inventory work (it derives from the authorized crawl); robots.txt exclusions are carried into the table, not worked around; the inventory is a map, not a copy — no verbatim harvesting of the target's copy or branded assets at this stage; gated pages are listed as gated, never accessed by bypass.

**Sources.** Wayback CDX Server API — https://github.com/internetarchive/wayback/blob/master/wayback-cdx-server/README.md ; migration inventory practice (crawl + sitemap + analytics + Search Console merge) — https://guestpost.uk/screaming-frog/

### design-extraction

**Core method.** Sample computed styles with browser automation across representative pages and interactive states (default, hover, focus, disabled, error). Collect raw color, type, spacing, radius, and shadow values; cluster near-identical values into single tokens (a spacing scale and palette are distributions, not single samples); record font stacks and type scales as found. Export as a DTCG-format token file (`$value`, `$type`, groups, aliases) and compile it with Style Dictionary so the rebuild consumes CSS variables/JS constants generated from that one file — never values typed per page.

**Key rules.**
- Extract values, not expression: tokens capture measurements (hex, px, font stack); the target's logo, wordmarks, and distinctive brand artwork are never tokenized or reused — they are flagged for replacement. **[→ D14]**
- Every token must trace to at least one sampled element on an authorized page; no invented "close enough" values.
- Font substitution is a recorded decision, not a silent one: if the source font is commercial and unlicensed for the rebuild, the inventory names the substitute and the visual delta is accepted explicitly.
- Extraction sampling follows the same access rules as discovery: public/authorized pages only, robots.txt honored for crawl-based sampling, no gated-state capture via bypass.

**Verification gates.**
- *Automatable:* script compares each token value against computed styles sampled from source pages; an unmatched token fails.
- *Automatable:* grep the rebuild's CSS for hex/font values present in no token; count must be zero.
- Manual: side-by-side render of one page per template using only the token file, checked against the source capture.

**Ethics constraints (binding).** Authorization required before sampling; robots.txt obeyed; no verbatim copying of trademarks, logos, or copyrighted design assets — measurements only, branding always replaced; no auth/paywall bypass to sample gated states.

**Sources.** Design Tokens Format Module 2025.10 — https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/ ; Style Dictionary — https://backlight.dev/docs/style-dictionary

### asset-harvesting

**Core method.** Extract asset URLs from HTML, CSS, JS, and network logs for every in-scope page; recover missing files from archived captures. Store captures in WARC containers (ISO 28500) with full request/response records — via a browser-driven archiver such as Browsertrix Crawler for JS-heavy pages — so provenance survives the live site changing or vanishing. Every asset gets a manifest row: source URL, capture date, checksum, and a rights decision — `owned`, `licensed`, `recreate`, or `replace`. Only `owned`/`licensed` assets ship as-is; the rest are recreated or replaced before build.

**Key rules.**
- No asset enters the rebuild without a manifest row and a rights decision; an undecided asset is treated as `replace`.
- Copyrighted photography, illustration, and copy are recreated or replaced, never silently reused — even when the client owns the site, third-party stock licenses are checked for transferability. **[→ D14]**
- Trademarks and logos are never harvested for reuse; they are logged so reconstruction knows what to replace.
- Harvest only from authorized targets at respectful rates; obey robots.txt for crawl harvesting; never pull assets from behind a login or paywall by bypass, and never hotlink the source CDN in the deliverable.

**Verification gates.**
- *Automatable:* manifest completeness — every file in the rebuild's asset folders has a manifest row with source URL and rights decision; orphans fail the gate.
- *Automatable:* checksum spot-check of harvested files against their WARC records.
- *Automatable:* grep the built site for the source domain in asset URLs (hotlink check); count must be zero.

**Ethics constraints (binding).** Authorization required before harvesting; robots.txt obeyed; no verbatim reuse of trademarks or copyrighted assets — the rights decision is the enforcement point; no auth/paywall bypass to reach asset files.

**Sources.** WARC Format 1.1 (IIPC, ISO 28500) — https://github.com/iipc/warc-specifications/blob/master/specifications/warc-format/warc-1.1/index.md ; Browsertrix Crawler (browser-based WARC/WACZ capture) — https://webrecorder.net/blog/2021-02-22-introducing-browsertrix-crawler/

### behavior-cloning

**Core method.** Drive the source site in a real browser and record each in-scope flow as a scripted interaction: the clicks and inputs, the expected state change after each step, and the network responses behind it (Playwright test scripts are the working format). Cover menus, forms and their validation messages, modals, filters, client-side routing, and animation triggers. The recordings become the rebuild's acceptance tests: development continues until the same scripts pass against the rebuild unchanged.

**Key rules.**
- Behavior is specified as executable tests, not prose impressions; a flow with no test is treated as uncloned.
- Interactions are recorded only on authorized targets, in the agent's own test accounts where accounts are needed — never with the site owner's or users' real credentials, and never by defeating a paywall. **[→ D14]**
- Behavior may be recreated; the content it surfaces may not be copied — form labels and flows are functional, but the target's marketing copy, help text, and branded assets are replaced, not transcribed verbatim.
- Test data is synthetic: recordings must not capture or replay real users' personal data from the source.

**Verification gates.**
- *Automatable:* the recorded interaction suite runs against the rebuild in CI; every in-scope interactive element has ≥1 passing test.
- *Automatable:* coverage report — inventory flow list vs. test list diff must be empty.
- Manual: click-through of the full flow list signed off against the checklist.

**Ethics constraints (binding).** Authorization required before recording; robots.txt obeyed for any crawl-assisted element discovery; no verbatim copying of the target's copy or branded assets while reproducing its behavior; no auth/paywall bypass — gated flows are recorded only through accounts the client legitimately provides.

**Sources.** Playwright Test (scripted interactions and assertions) — https://playwright.dev/docs/test-snapshots ; Browsertrix browser profiles for authorized logged-in capture (contrast: legitimate provisioned access, not bypass) — https://webrecorder.net/browsertrix/

### page-reconstruction

**Core method.** For pages that cannot be captured directly — auth-gated, deleted, or never archived — rebuild from surviving evidence in strict priority order: (1) dated Wayback captures (the CDX `digest` field establishes what a capture actually contained), (2) JS bundle route manifests, sitemap hints, and API responses that reveal structure, (3) the extracted design system and component patterns. Every inventory row is labeled `captured`, `inferred`, or `designed`. Only `captured` pages may claim parity; `designed` pages are new design in the source's system and are presented to the client as such.

**Key rules.**
- Evidence hierarchy is binding: no page is reconstructed from a lower tier while a higher-tier source exists unchecked.
- A designed page never carries a parity or "clone" claim in any deliverable, report, or filename.
- Reconstruction recreates layout and function from evidence; it does not resurrect the target's copyrighted text, photography, or trademarks verbatim — recovered copy is used as a structural reference and replaced unless the client owns the rights. **[→ D14]**
- Gated pages are reconstructed from client-provided access or evidence only; their absence from archives is never treated as a reason to bypass the gate.

**Verification gates.**
- *Automatable:* inventory audit — every row carries a `captured`/`inferred`/`designed` status; any row missing a status fails.
- *Automatable:* claim check — grep deliverable docs and page metadata for parity language attached to `designed` rows; matches fail.
- Manual: spot-check each inferred route against the bundle route manifest or a capture.

**Ethics constraints (binding).** Authorization required (reconstruction scope is set by the same D14 record); robots.txt obeyed for any supporting crawl; no verbatim copying of trademarks or copyrighted assets — evidence informs structure, rights decide content; no auth/paywall bypass to obtain "evidence."

**Sources.** Wayback CDX Server API (capture/digest lookup) — https://github.com/internetarchive/wayback/blob/master/wayback-cdx-server/README.md ; Design Tokens Format Module 2025.10 (the system designed pages are built from) — https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/

### fidelity-verification

**Core method.** Compare source and rebuild in the same browser engine at the viewports agreed before the comparison runs: screenshot both, pixel-diff against committed golden baselines (Playwright visual comparisons produce expected/actual/diff images per failure), and compare DOM structure alongside. Dynamic regions (timestamps, rotating content) are masked by rule, not by hand-waving. The OmniForge bar: ≥95% pixel similarity on key viewports, plus a passed interaction checklist for every in-scope element (from `behavior-cloning`). Baseline changes require a recorded reason and re-approval — baselines are evidence, not a rubber stamp.

**Key rules.**
- Thresholds and viewports are fixed in writing before the first comparison run; they are not renegotiated after a failure.
- A baseline is regenerated only with a recorded reason tied to an approved change; silent regeneration is treated as a falsified result.
- Fidelity is measured against the authorized capture set (WARC/CDX captures), so the comparison target cannot drift with the live site.
- Verification never requires defeating the target's protections: if a source view can't be captured within authorization and robots rules, it is excluded from scoring and reported as unverified, not bypassed.

**Verification gates.**
- *Automatable:* visual suite runs in CI against committed baselines; per-page diff report must show ≥95% similarity on key viewports.
- *Automatable:* baseline-change audit — any changed baseline file without a matching reason record fails the gate.
- *Automatable:* interaction checklist shows zero untested in-scope elements.

**Ethics constraints (binding).** Authorization required (verification uses the authorized captures); robots.txt obeyed for any fresh source screenshots; comparison reports must not reproduce the target's copyrighted assets or trademarks beyond fair-use thumbnails needed for the diff itself; no auth/paywall bypass to capture a scoring screenshot.

**Sources.** Playwright visual comparisons — https://playwright.dev/docs/test-snapshots ; crawl-comparison practice in migration QA — http://umatechnology.org/best-seo-site-migration-monitoring-tools-for-redirects-crawling-and-indexing/

## 4. Open risks for Phase 3

- **Wayback coverage is not guaranteed.** Small, new, or robots-excluded sites may have few or no CDX captures; skills must specify the fallback (client-provided exports, analytics lists) instead of assuming archive evidence exists. Note the tension: a site whose robots.txt excludes archiving may also be signaling against capture generally — Phase 3 should route that case to D14 explicitly. **[→ D14]**
- **The ≥95% pixel bar is engine- and font-sensitive.** Sub-pixel rendering, font availability (licensed source fonts often cannot be shipped), and anti-aliasing differences can fail pages that are visually identical to a human. Phase 3 must define the masking rules, the licensed-font substitution policy, and whether the bar is per-page or aggregate before drafting the gate.
- **WARC tooling weight.** Browsertrix/pywb gives archive-grade capture but is heavy for small rebuilds; Phase 3 needs a documented lightweight tier (HAR + screenshot set) and the criteria for choosing, or the skill will be skipped in practice.
- **Behavior tests rot.** Recorded interaction suites depend on source-site stability; if the source changes mid-engagement, tests fail against the source itself. Phase 3 should require freezing the evidence set (captures + recordings) at inventory sign-off.
- **Rights decisions need an owner.** The `owned/licensed/recreate/replace` call in `asset-harvesting` is a legal judgment an agent can prepare but D14 must own; Phase 3 should not let the harvesting skill self-approve `licensed`. **[→ D14]**
- **Analytics access is client-dependent.** The inventory standard assumes analytics/Search Console data; without client cooperation the fourth source is missing and the reconciliation gate weakens. Phase 3 should define the three-source minimum behavior.
